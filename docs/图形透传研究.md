# GPU passthrough research (Roadmap Phase 5)

Status: research spike, not a shipping feature. The framebuffer bridge
(mmap -> ANativeWindow blit) remains the supported display path.

## What we tried

- **VirGL / gfxstream (ranchu)**: needs a host-side GL transport plus
  guest-side `ro.hardware.gralloc` support. Works in the Android Emulator
  because the emulator process owns both ends; inside an app sandbox we
  cannot open the host `/dev/dri` nodes most devices would need.
- **AHardwareBuffer passthrough**: guest renders to a host-shared buffer.
  Requires the guest kernel to expose the same dma-buf heap the host
  compositor accepts. On GKI kernels this fails closed (no heap, no share).
- **Vulkan via SwiftShader**: pure-CPU fallback, always available but
  slower than the current RGB565/RGBA blit for 2D workloads.

## Decision

Keep the framebuffer blit as default. Revisit only if:

1. A device exposes a shareable dma-buf heap to the app UID, and
2. A guest ROM can be built against that heap's gralloc HAL.

Both are device-specific, so this stays a per-device experiment tracked
in GitHub issues, not a roadmap blocker.
